01 · Pre-train

Check the data before you train on it.

POST/pretrain/checks

  • Test items leaking into training data
  • Duplicates and near-duplicates
  • Label quality on a sampled audit
  • Coverage of the groups and cases you'll claim
  • Licensing and personal-data flags
request.json
{
  "dataset": "s3://acme/train-v7",
  "eval_sets": ["s3://acme/heldout-q4"],
  "checks": ["leakage", "dedup", "labels", "coverage", "pii"],
  "claim": "Answers product questions correctly"
}
200 · response.jsonFAIL
{
  "verdict": "FAIL",
  "coverage": "5/5",
  "findings": [
    { "id": "P-03", "check": "leakage",
      "result": "412 eval items found in train" },
    { "id": "P-09", "check": "coverage",
      "result": "non-English: 2% of rows" }
  ],
  // board read: fix the leak before training
}

02 · Intra-train

Check every checkpoint while the run is live.

POST/intratrain/checkpoints

  • Held-out score on each checkpoint, with its interval
  • Regression against the previous checkpoint
  • GPU hours and cost per point gained
  • A stop signal when gains stall, and ABSTAIN when history is too short
request.json
{
  "run_id": "acme-7b-v7",
  "checkpoint": "step-48000",
  "suite": "heldout-q4",
  "compare_to": "step-44000",
  "webhook": "https://acme.dev/hooks/iot"
}
202 · response.jsonPASS
{
  "verdict": "PASS",
  "score": 0.874, "ci95": [0.866, 0.882],
  "delta_vs_prev": +0.006,
  "gpu_hours": 312,
  "cost_per_point": "$5,200",
  "signal": "gains slowing; review at step-52000"
}

03 · Forward-train

Carry the verdict into the launch and the next run.

POST/forwardtrain/gates

  • Go/no-go against thresholds agreed in writing
  • Red-team suite on the release candidate
  • A production baseline for drift and recheck
  • What to fix in the next run's data, written down
request.json
{
  "candidate": "acme-7b-v7@step-52000",
  "gates": { "accuracy_min": 0.85, "injection_max": 0.01 },
  "redteam": true,
  "recheck": "weekly"
}
200 · response.jsonABSTAIN
{
  "verdict": "ABSTAIN",
  "gates": { "accuracy": "PASS", "injection": "not run: tools 6-8" },
  "baseline_id": "bl_7f3a",
  "next_run": ["add non-English rows", "drop leaked items"],
  // board read: ship after tools 6-8 are tested
}

04 · Local · free

Check the system against itself.

POST/kg/self-check· runs on your machine

  • Builds a knowledge graph of what your system claims and answers
  • Scoped to what each user can access, nothing more
  • Flags where it contradicts itself across answers, versions and users
  • Free, local, unlimited runs
request.jsonlocalhost
{
  "system": "acme-assistant@v7",
  "scope": "user:me",
  "compare": ["answers", "versions"],
  "since": "30d"
}
200 · response.json2 conflicts
{
  "nodes": 1840, "edges": 5122,
  "conflicts": [
    { "claim": "refund window",
      "says": ["30 days", "14 days"], "since": "v7" },
    { "claim": "EU data stays in EU",
      "says": ["yes", "routes via us-east"] }
  ],
  // fewer conflicts = a system you can stand behind
}
