What we check

What we check depends on what you ship

Shipping an LLM feature

Tests pass, and the model still changes between versions.

  • Regressions between prompt or model versions
  • Prompt injection and outputs your policy forbids
  • Whether the test set is big enough for a pass to mean something
  • A go/no-go bar agreed before launch day
Learn more: Launch gating and pipelines

Agents that call tools

Benchmarks say the task got done, not that the agent is safe to let loose.

  • Actions outside the user's role or the agent's allowlist
  • Instructions hidden in tool results
  • Lost state over long or ambiguous tasks
  • Logs complete enough to audit
Learn more: AI security assessment

Models in production

Quality drops slowly, and nobody is watching the right dashboard.

  • Drift against an agreed baseline
  • A forecast of when a threshold will break
  • An alert when data goes stale, not silence
  • No verdict on too little history
Learn more: Agent ops

Connected devices and hardware

It works on the bench. The question is ten thousand units, in the field, a year from now.

  • Sensor accuracy and drift across units, batches and environments
  • On-device models under real power, memory and latency limits
  • Firmware updates: what breaks between versions, and whether rollback works
  • Device-to-cloud security: pairing, credentials and data in transit
Learn more: Connected hardware check

How engagements run

One project, or checks that keep up with your releases

A project

The Diagnostic, an eval audit or a security assessment. Fixed scope, deep testing, a report at the end.

Ongoing

Launch gating on every release, agent ops monthly, or a fractional head of evaluation. The checks move as your model and prompts change.

Re-check

The same checks re-run against what you ship now, so a report doesn't go stale after a year or a new version.

Fixes

When a claim fails, the report says what to change. Re-checking the fix is scoped with you up front.

Eval audit EA

Book a demo
For
